SECTION 01프로젝트 전체 개요 및 파일 간 상호작용

Trip.AI 코드 파일(초안)은 사용자의 여행 조건(출발 집 위치, 여행지, 숙소, 여행 기간, 세부 시간, 6종 이동 교통수단 조합)을 입력받아 AI 맞춤형 여행 일정을 생성하고, 장소별 확정·보류(차선책 교체) 및 대화형 재요청을 거쳐 최종 일정 타임라인, 구간별 예상 교통비, 실제 도로 기반 루트 지도를 제공하는 웹 애플리케이션입니다.

SECTION 02Trip.html 상세 분석 — 프론트엔드 메인 애플리케이션

Trip.html은 별도의 빌드 도구나 프레임워크 없이 브라우저에서 즉시 동작하도록 HTML 마크업 + 커스텀 다크 테마 CSS + 8개 모듈의 JavaScript 로직을 단일 파일에 담아낸 애플리케이션입니다. LLM이 연결되지 않은 상태에서도 내장된 제주도 샘플 데이터와 OpenStreetMap API만으로 전체 기능을 체험할 수 있도록 설계되어 있습니다.

2.1 Trip.html이 담당하는 4대 핵심 역할

역할 1여행 조건 수집 및 상호배타 규칙 제어 (Step 1)

출발/복귀 집 위치, 여행지, 숙소, 기간, 식사 횟수(1~3끼), 세부 시간(시작·숙소 복귀·마지막 날 체크아웃)을 입력받습니다. 한글 유니코드 분해 기반의 초성 자동완성(예: ㄱㄹ → 강릉시, ㅁㅍ → 목포시)과 6종 교통수단 선택 규칙(자가용 단독 선택 강제, 나머지 5종 복합 조합 허용)을 실시간 제어합니다.

역할 2AI 일정 초안 생성 및 확정·보류 워크플로우 (Step 2)

사용자 조건과 JSON 스키마를 조합해 LLM에 일정을 요청합니다. 제안된 각 장소 카드는 우측에 다크톤 Google 미니 지도를 표시하며, [보류 (차선책)] 선택 시 대체 장소(alternatives) 목록을 펼쳐 즉시 교체·확정할 수 있습니다. 자연어 AI 재요청과 이전 목록 되돌리기(Undo)도 지원합니다.

역할 3타임라인·교통비 계산 및 버스 vs 택시 비교 (Step 3 좌측)

첫날 집 출발부터 마지막 날 숙소 체크아웃(checkoutTime) 후 집 복귀까지 분 단위로 시간을 누적 계산합니다. 구간별 거리(Haversine × 보정계수 1.28)를 바탕으로 항공·여객선·렌터카·자가용·버스·택시 비용과 소요 시간을 산출하며, 대중교통+택시 모드에서는 구간별로 두 수단을 클릭해 전환·비교할 수 있습니다.

역할 4인터랙티브 루트 지도 및 주변 추천 탐색 (Step 3 우측)

Leaflet 지도 위에 5종 배경 타일(구글 다크/일반/위성, OSM 다크/일반)과 숨쉬기(Breathing) 마커를 표시합니다. 지역 내 이동은 OSRM으로 실제 도로 곡선 경로와 구간 중앙 교통수단 아이콘을 그리며, 루트 주변 추천 더 보기를 통해 AI 또는 Overpass API로 반경 1.5km 내 명소를 추가 탐색합니다.

SECTION 03server/llm-proxy.js 상세 분석 — 백엔드 LLM 프록시 서버

server/llm-proxy.js는 외부에 공개되는 웹사이트 운영 시 브라우저에 GEMINI_API_KEY가 노출되지 않도록 서버 측에서 대신 Gemini API를 호출해 주는 백엔드 프록시입니다. 별도의 npm install 과정 없이 Node.js 18+ 내장 모듈(http, fetch)만으로 동작하도록 106줄로 응집도 높게 구현되어 있습니다.

3.1 server/llm-proxy.js의 3대 핵심 역할

  • API 키 서버 은닉 및 실행 보호: 클라이언트는 API 키를 전혀 알 필요 없이 POST /api/llm으로 프롬프트만 보내고, 서버는 운영체제 환경변수(process.env.GEMINI_API_KEY)에서 키를 읽어 Google 서버와 통신합니다. 환경변수가 없으면 즉시 구동이 중단(process.exit(1))됩니다.
  • 보안 가드 및 페이로드 용량 제한: 요청 스트림을 읽는 단계에서 MAX_BODY(200KB) 초과 시 즉시 소켓을 파기(req.destroy())하여 비정상적인 대용량 요청을 차단하고, POST /api/llm 외의 모든 경로에 404 Not Found를 반환합니다.
  • 모델별 추론(Thinking) 제어 및 폴백: responseMimeType: 'application/json' 강제 지정과 함께 모델별 thinkingConfig를 설정하며, 호환되지 않는 모델에서 400 응답이 오면 자동으로 일반 모드로 재시도한 뒤 내부 추론 파트(p.thought)를 제외한 최종 텍스트만 추출합니다.

SECTION 04두 파일의 연동 흐름 및 Nginx 운영 가이드

  1. 프롬프트 생성 (Trip.html): 사용자가 일정 생성, AI 재요청, 또는 주변 추천 더 보기를 실행하면 buildItineraryPrompt() 또는 fetchNearbyFromLLM()이 여행 조건과 JSON 스키마를 조합합니다.
  2. 프록시 호출 (Trip.html → Nginx): callLLM() 함수가 POST /api/llm 엔드포인트로 { system, prompt } JSON 페이로드를 전송합니다.
  3. 리버스 프록시 전달 (Nginx → llm-proxy.js): Nginx가 /api/ 요청을 로컬 루프백(http://127.0.0.1:8787/api/llm)에서 대기 중인 Node.js 프로세스로 포워딩합니다.
  4. Gemini 대리 호출 및 정제 (llm-proxy.js → Google): callGemini()가 서버의 GEMINI_API_KEY로 Gemini API를 호출하고 순수 JSON 응답 텍스트를 추출해 200 { "text": "..." }로 반환합니다.
  5. 정규화 및 UI 렌더링 (Trip.html): parseLLMJson()과 normalizeItinerary()가 응답을 검증·정규화하여 Step 2 장소 카드 또는 Step 3 타임라인·지도를 즉시 업데이트합니다.
Nginx 연동 및 서버 구동 시 핵심 체크포인트
• PowerShell 프록시 서버 실행: $env:GEMINI_API_KEY="발급받은_API_키"; node server/llm-proxy.js
• Nginx 설정 (conf/nginx.conf): server { ... } 블록 내부에 location /api/ { proxy_pass http://127.0.0.1:8787; proxy_read_timeout 120s; }를 추가한 뒤 nginx -s reload를 실행하고, Trip.html 우측 상단 [AI 설정] → [백엔드 프록시] → URL: /api/llm으로 저장하면 연동이 완료됩니다.
